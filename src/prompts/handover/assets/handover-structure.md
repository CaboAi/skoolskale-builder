# Handover Structure — output layout + index template (deliverable 00)

Every run produces one folder: `handovers/<slug>/` (slug from the community name, kebab-case). Files are numbered so they read in launch order.

```
handovers/<slug>/
├─ 00-README.md                     # index + placeholder checklist + launch timeline
├─ 01-vsl-and-cancellation.md       # the VSL IS the About-Us page script — no separate 01-about-us file
├─ 02-pre-launch-emails.md          # guest-send section ONLY if the user confirms launch guests
├─ 03-post-launch-emails.md
├─ 04-docuseries-full-script.md     # word-for-word only — no talking-points file
└─ 05-dm-sequences.md
```

## `00-README.md` template

```markdown
# <Community> — Launch Handover
_<Creator> · <niche> · <tone> · generated <DATE> from Pre-Skool DNA_

**Transformation:** <transformation_line>
**Audience:** <audience>
**Offer:** <tier summary, e.g. Free · Premium $27/mo·$227/yr · VIP $57/mo·$477/yr>
**Guest sessions:** <yes/no> · **Trial:** <terms> · **Refund:** <terms>

## Deliverables
| # | File | What it is |
|---|------|------------|
| 01 | vsl-and-cancellation.md | Long VSL (**also the About-Us page script**) + cancellation/retention video |
| 02 | pre-launch-emails.md | List warm-up to the launch event (+ guest emails only if confirmed) |
| 03 | post-launch-emails.md | Doors-open → founding-window conversion |
| 04 | docuseries-full-script.md | The film/episodes, word-for-word |
| 05 | dm-sequences.md | Skoot DMs: welcome / free nurture / declined / cancel |

## ⚠️ Placeholders to fill before use
Every `[[…]]` below needs a real value from the creator. Nothing here was fabricated.
- [ ] `[[CREATOR STORY: …]]` — appears in: 02, 05, 06
- [ ] `[[EVENT DATE]]` — 03
- [ ] `[[EPISODE 1 LINK]]` / `[[EPISODE 2 LINK]]` — 03, 04
- [ ] `[[SKOOL COMMUNITY LINK]]` / `[[SKOOL JOIN LINK]]` — 03, 04
- [ ] `[[FOUNDER RATE ENDS: date/time]]` — 02, 05, 06
- [ ] `[[PROOF / TESTIMONIAL: …]]` — 04, 05, 06
- [ ] `[[PRICE INCREASE DATE]]` — 04
  (auto-generate this list by scanning every emitted file for `[[…]]`)

## Suggested launch timeline
- **T-10 → T-1 days:** send pre-launch emails (03); publish About-Us VSL (01) on the Skool About page; open the free community.
- **T-0:** Episode 1 goes live. Send "it's live" email.
- **T+1–2 days:** Episode 2 goes live (doors open, founding window starts). Start post-launch emails (04).
- **Ongoing:** set up Skoot DM flows (07); publish the long VSL (02) on the paid-upgrade page.
- **T+72h:** founding window closes; price steps up (if configured).
```

## Rules
- The README's placeholder checklist is generated by scanning all emitted files for `[[…]]` tokens and de-duplicating — it must be complete and accurate.
- Date: stamp the real generation date (from the environment/session, e.g. today's date) — do not hardcode.
- Keep the README skimmable — it's the first thing the creator/operator opens.
